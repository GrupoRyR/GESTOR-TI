# Stage A · Connect the design frontend (PR #8) to the backend

Source of truth for page contracts: design branch `claude/diseno-gestor-ia-a5a314` (GrupoRyR/GESTOR-TI#8):
`docs/design/stage-a-contract.md`, `resources/js/types/shared.ts`, `resources/js/types/pages/*.ts`, `resources/js/mocks/*`.

## Objective
Every Stage A page of the design renders against the real backend with exactly the props of its type,
each covered by an `assertInertia` test, and the front-end builds (Laravel Vite + design `ui-preview`).

## Decisions
- 2026-10-09 (user): `ai.projects.approve` only through role "Aprobador de proyectos" (Jhon Castro, Edward Ramanan `edward.ramanan@segurex.com`). Removed from Súper Admin and Líder IA.
- Inertia client: keep v3 (server is inertia-laravel v3); design code is re-verified with `npm run typecheck`; breakages in design-owned files are flagged to design, not restyled.
- Home `view`: `it` when the user has `ai.manage`, otherwise `requester`. Stage B data (requests, approvals, vault, monitoring) ships empty in Stage A; Stage B routes exist as placeholders so Ziggy never throws.
- Design-only routes/pages replace the backend placeholders (`Dashboard` → `Home`, `Admin/Employees/*` → `Employees/*`, `Profile/Notifications` → `Profile/Edit`, `Admin/DepartmentMappings` folded into `Admin/Areas`). Backend pages without design (`Employees/Show`, `Notifications/Index`) stay until designed.
